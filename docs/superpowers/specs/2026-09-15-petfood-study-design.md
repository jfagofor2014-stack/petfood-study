# ペットフード販売士 学習アプリ 設計書

作成日: 2026-09-15
対象端末: Pixel 8a (Android Chrome)
公開方法: GitHub Pages

## 1. 背景と目的

一般社団法人ペットフード協会が認定する「ペットフード販売士」の認定試験に合格するための
学習アプリを作る。公式教材は紙のテキスト（第5版・全154ページ）と eラーニング動画のみで、
スキマ時間に反復学習する手段がない。

### 試験の要件（調査結果）

| 項目 | 内容 |
|---|---|
| 主催 | 一般社団法人ペットフード協会／ペットフード販売士認定委員会 |
| 形式 | CBT（全国350以上のテストセンター） |
| 出題 | 四肢択一式 25問／60分 |
| 合格基準 | 非公開 |
| 受験料 | 33,000円（税込） |
| 2026年度日程 | 申込 8/1〜11/6 ／ 受験 10/1〜11/30 ／ 合格発表 12/11 13:00 |
| 資格有効期限 | 交付から3年（更新講習で維持） |
| 出題範囲 | 専門テキストの全範囲（テキストp5に明記） |

設計上の含意:

- **捨て章を作れない。** 25問に対し範囲が154ページ全域なので、どの章からも出る。
  全章を確実に1周させる導線が最優先。
- **公式の過去問は存在しない。** 模擬試験の問題はテキストから作成する「範囲準拠の予想問題」であり、
  本番と同一ではない。この点はアプリ内に明示する。
- **原典はスキャンPDF（テキスト層なし）。** OCR済みテキストをアプリに内蔵する。

### 教材の構造

全10章・85節。1節あたり平均1.8ページ、読み上げ時間にして2〜5分。
この「節」を再生・進捗・テストの共通単位とする。

| # | 章 | 開始頁 | 節数 |
|---|---|---|---|
| 1 | ペットフード販売士認定制度の概要 | 4 | 10 |
| 2 | 犬・猫の体の構造と生理 | 8 | 11 |
| 3 | 犬・猫の栄養に関する基礎知識 | 28 | 5 |
| 4 | ペットフードの関連法規 | 48 | 4 |
| 5 | ペットフードについて | 58 | 3 |
| 6 | ペットフードの製造・保管 | 64 | 8 |
| 7 | 店頭や動物病院でのQ&A | 85 | 11 |
| 8 | ペット飼育の基礎マナー | 99 | 11 |
| 9 | エキゾチックアニマル・鳥・観賞魚 | 116 | 8 |
| 10 | ペット飼育の効果・効用 | 141 | 11 |

## 2. スコープ

### 今回作るもの

- テキスト全文の読み上げ（速度調整・一時停止・文単位スキップ・文ハイライト）
- 中断した位置からの再開
- もくじと進捗管理
- 節ごとの確認テスト（4択）と苦手リスト
- PWA としてのオフライン動作

### 今回作らないもの

- 本番形式の模擬試験画面（25問60分・タイマー付き）。
  ただし問題データは最初から25問抽出できる形で持たせ、画面を足すだけで済むようにする。
- フラッシュカード画面。同じく問題データを流用できる形にしておく。
- 複数端末間の同期。localStorage のみ。
- アカウント機能。

## 3. アーキテクチャ

Vanilla JS の単一ページアプリ。ビルドステップなし。GitHub Pages に静的配信する。

```
index.html
css/style.css
js/
  app.js          エントリ、タブ切替
  player.js       読み上げエンジンと再生制御
  speech.js       speechSynthesis のラッパ（Android Chrome 対策を閉じ込める）
  progress.js     進捗と再生位置の永続化
  quiz.js         確認テスト
  toc.js          もくじ
data/
  content.json    テキスト全文（章→節→ブロック→文）
  quiz.json       問題
img/              図表の切り出し画像
sw.js             Service Worker
manifest.json
icons/
```

**教材は静的JSON、状態は localStorage** の二層構造。通信もAPIキーも不要。

### 責務の分離

| モジュール | 責務 | 依存 |
|---|---|---|
| `speech.js` | 文字列を喋る／止める／速度を変える。Android Chrome の不具合対策をここに閉じ込める | なし（ブラウザAPIのみ） |
| `player.js` | 「今どの節のどの文か」を管理し、speech.js に1文ずつ渡す | speech, progress, content |
| `progress.js` | 再生位置・節ごとの読了状態・テスト成績の読み書き | localStorage |
| `toc.js` | 章節の一覧表示と選択 | progress, content |
| `quiz.js` | 出題・採点・苦手リスト | progress, quiz.json |
| `app.js` | タブ切替と初期化 | 全部 |

`speech.js` は他のどのモジュールも知らない。ブラウザの読み上げ仕様が変わっても、
修正はこのファイル内に閉じる。

## 4. データモデル

### content.json

```js
{
  "meta": {
    "title": "ペットフード販売士認定講習会テキスト",
    "edition": "第5版",
    "publisher": "一般社団法人ペットフード協会",
    "totalPages": 154,
    "generatedAt": "2026-09-15"
  },
  "chapters": [
    {
      "id": "ch03",
      "no": 3,
      "title": "犬・猫の栄養に関する基礎知識",
      "page": 28,
      "sections": [
        {
          "id": "ch03-s01",
          "no": 1,
          "title": "犬・猫の食の歴史",
          "page": 28,
          "blocks": [
            {
              "type": "p",
              "sents": [
                "犬の先祖は、オオカミやコヨーテといった野生動物と言われている。",
                "オオカミは、大型の有蹄類を獲物として捕食し、中でも内臓を好んで真っ先に食していく。"
              ]
            },
            {
              "type": "figure",
              "img": "img/p032.png",
              "caption": "表1 犬の1日あたりの必要エネルギー量",
              "speak": "表。犬の1日あたりの必要エネルギー量。体重5キロの成犬でおよそ374キロカロリー。"
            }
          ]
        }
      ]
    }
  ]
}
```

ブロック種別は `p`（段落）、`list`（箇条書き）、`figure`（図表）、`note`（囲み・補足）の4種。

**段落をあらかじめ文の配列に分解しておくことが設計の要。** 理由は3つ:

1. 再生位置が `{sectionId, sentIndex}` の2値だけで完全に表現でき、中断・再開が正確になる
2. 読み上げ中の文をハイライトできる
3. Android Chrome の speechSynthesis は長文を渡すと途中で停止する既知の不具合があるが、
   1文ずつ渡せば回避できる

文への分割は `。` `！` `？` を境界とする。ただし括弧内・鉤括弧内の句点では分割しない。

### quiz.json

```js
{
  "questions": [
    {
      "id": "q0301",
      "sectionId": "ch03-s01",
      "chapterNo": 3,
      "type": "choice4",
      "difficulty": 2,
      "question": "猫が動物組織の摂取からしか十分量を得られない栄養素の組み合わせとして正しいものはどれか。",
      "choices": [
        "タウリン、ビタミンA、アラキドン酸",
        "タウリン、ビタミンC、リノール酸",
        "カルニチン、ビタミンD、アラキドン酸",
        "タウリン、ビタミンK、オレイン酸"
      ],
      "answer": 0,
      "explanation": "猫は内臓の植物成分を食べない。これはタウリン、ビタミンA、アラキドン酸を動物組織から得る必要があるためである。",
      "page": 28
    }
  ]
}
```

`chapterNo` と `difficulty` を最初から持たせることで、次フェーズで
「全章から25問をバランス良く抽出」する模擬試験を、データを作り直さずに実装できる。

### localStorage スキーマ

キーは `pfs:` 接頭辞で名前空間を切る。

| キー | 内容 |
|---|---|
| `pfs:position` | `{sectionId, sentIndex, updatedAt}` — 最後の再生位置 |
| `pfs:progress` | `{[sectionId]: {state:"unread"\|"reading"\|"done", maxSent, doneAt}}` |
| `pfs:settings` | `{rate, voiceURI, pauseMs, keepAwake}` |
| `pfs:quiz` | `{[questionId]: {attempts, correct, lastResult, lastAt}}` |
| `pfs:schema` | スキーマ版番号。将来のマイグレーション用 |

## 5. 読み上げの設計

### 基本ループ

```
再生開始
  → 現在の節の blocks を文の平坦な配列に展開
  → sentIndex の文を utterance にして speak()
  → onend で sentIndex++ 、位置を localStorage に保存
  → 節の末尾に達したら「読了」を記録し、次の節へ自動で進む
```

文が終わるたびに位置を保存するため、アプリが強制終了しても最大1文しか戻らない。

### Android Chrome 固有の対策

| 問題 | 対策 |
|---|---|
| 初回の `speak()` がユーザー操作なしでは無音になる | 最初の再生ボタンのタップで空の utterance を発話し、音声をアンロックする |
| 長文で途中停止する | 1文ずつ渡す（データモデルで担保済み） |
| 画面が消えると読み上げが止まる | Wake Lock API で再生中は画面を点灯維持。設定で既定ON、切ることもできる |
| `getVoices()` が初回は空配列を返す | `voiceschanged` イベントを待ってから声リストを構築する |
| バックグラウンド復帰時に状態が壊れる | `visibilitychange` で復帰を検知し、保存済み位置から再開する |

**バックグラウンド再生はできない。** Android Chrome は非表示タブの speechSynthesis を停止する。
これは回避策のない仕様なので、「再生中は画面を消さない」ことを既定動作とし、
その旨をアプリ内で説明する。

### 再生コントロール

- 再生／一時停止
- 速度 0.5〜2.0倍（0.1刻み）。設定に保存
- 1文戻る／1文進む
- 節の先頭へ戻る／次の節へ
- 文間の間（0〜1000ms）。聞き取りやすさの調整用

### 図表の扱い

`figure` ブロックに到達したら、画面に画像を表示しつつ `speak` フィールドの要約文を読み上げる。
表をそのまま読み上げても頭に入らないため、**要点だけを文章化した読み上げ用テキストを別途用意する。**

## 6. 画面構成

4タブ構成。既存の GACHI-FIT と同じ流儀。

### きく（メイン）

- 画面上部: 現在の章・節、節内の進捗バー
- 中央: 本文。読み上げ中の文をハイライトし、自動スクロールで追従
- 文をタップするとその文から再生
- 下部: 再生コントロール
- 図表は本文中にインラインで表示、タップで拡大

### もくじ

- 10章のアコーディオン。各章に進捗バー
- 節ごとに 未読／途中／読了 のバッジと、途中なら「12文目」等の位置表示
- 章単位の「この章を最初から」ボタン

### テスト

- 節を選んで確認テスト、または「苦手だけ」「章まとめ」を選択
- 4択。回答すると即座に正誤と解説を表示し、該当ページ番号も出す
- 終了後に成績と、間違えた問題の節へのリンク

### 設定

- 声の選択（端末にある日本語音声の一覧）
- 既定の速度、文間の間
- 再生中に画面を消さない（既定ON）
- 進捗のリセット、学習データのエクスポート／インポート（JSON）

### 起動時

画面最上部に常に **「前回の続きから」** カードを出す。
例: 「第3章 3-2 栄養素のはたらき ／ 12文目から」。
これが中断・再開要件の中核であり、最も目立つ位置に置く。

## 7. 本文データの作成手順

工数の大半を占める。

1. `pdftoppm -r 300` で154ページをPNG化
2. macOS Vision Framework（`VNRecognizeTextRequest`, ja-JP）でOCR。精度は高いが完全ではなく、
   実際に「幸せな暮らじ」「不可な栄養成分」等の誤りを確認済み
3. **154ページ全ページをページ画像で目視し、OCR結果と突き合わせて校正する。**
   10ページずつ16バッチ程度。33,000円の試験の教材として誤字は許容できない
4. 校正と同時に、行を段落に結合し、段落を文に分割する
5. 表・図を切り出して `img/` に保存し、読み上げ用の要約文 `speak` を書く
6. `content.json` を生成

OCRの生データと中間ファイルはリポジトリに含めない（`tools/` 配下に生成スクリプトのみ置く）。

### 著作権の扱い

本テキストは一般社団法人ペットフード協会の著作物である。
本アプリは受験者本人の私的学習のためのものであり、リポジトリは
**GitHub Pages で配信するが、本文データの再配布を意図しない。**
リポジトリを public にする場合、`data/content.json` は含めず、
利用者が自分のテキストから生成する手順のみを置く構成も選べる。
この判断は実装前に確認する。

## 8. テスト方針

- `speech.js` はブラウザAPIに強く依存するため、`speechSynthesis` をモックした
  ユニットテストで「1文ずつ順に投げること」「onend で次へ進むこと」を検証する
- 文分割ロジック（括弧内の句点で切らない等）はユニットテストの対象
- `progress.js` の localStorage 読み書きとマイグレーションはユニットテスト
- 画面まわりは Pixel 8a 実機で確認する

## 9. リスクと未解決事項

| リスク | 対応 |
|---|---|
| OCR校正の作業量が大きい | 章ごとに区切って進め、第1章が終わった時点でアプリと繋いで動作確認する |
| 図表の読み上げ用要約は主観が入る | 原文の数値・項目は削らず、順序と接続詞のみ補う方針とする |
| 予想問題が本番と乖離する | アプリ内に「本問題は公式過去問ではない」と明示する |
| 端末の日本語音声が期待通りでない | 設定で声を選べるようにし、Google音声が無い場合のフォールバックを用意 |

## 10. 実装の順番

1. 本文データ整備（校正・図表処理）→ `content.json`
2. アプリ本体（きく・もくじ・設定・PWA）
3. 確認テスト作成 → `quiz.json` ＋ テスト画面
4. GitHub Pages 公開、Pixel 8a 実機確認
