# 残課題の解消 設計書

作成日: 2026-10-06
対象: ペットフード販売士 学習アプリ（`/Users/taichi/petfood-study`）
前提となる設計書: `2026-09-22-mock-exam-design.md` / `2026-09-29-safe-storage-design.md` / `2026-09-30-flashcards-design.md`

前の3つのブランチ（模擬試験・保存失敗対策・フラッシュカード）のレビューで持ち越した3件を解消する。

## 1. 保存できないときでも模擬試験を受けられるようにする

### 現状

保存に失敗している端末で「模試を開始する」を押すと、何も起きずにトップへ戻る。

`startExam()` は中断データを `mockState.saveActive()` で保存したあと `drawExam()` を呼ぶ。
`drawExam()` は `mockState.getActive()` で**保存内容を読み直す**。保存が失敗していると
`null` が返るので `drawHome()` に戻ってしまう。

### 方針

**開始を断るのではなく、メモリ上で最後まで受けられるようにする。** 保存できないのは
「中断して後で再開できない」ことを意味するだけで、目の前の60分を解けない理由にはならない。
保存に失敗していることは画面上部の帯が既に伝えている。

- `drawExam(active)` が中断データを引数で受け取れるようにする。省略時は従来どおり `mockState.getActive()` から読む
- `startExam()` は `saveActive()` が返した状態をそのまま `drawExam(saved)` に渡す
- 再開ボタンは引数なしで `drawExam()` を呼ぶ（保存済みのものを読む）

注意: 再開ボタンを `addEventListener('click', drawExam)` のまま登録すると、`drawExam` の第1引数に
クリックの `Event` が入ってしまう。`() => drawExam()` に変えること。

`js/lib/mockstate.js` は変更しない。

### 作らないもの

- 保存できない状態で、タブ移動をまたいで模試を保持する仕組み。保存失敗はまれで、
  帯が「この端末に残らない」ことを伝えている

## 2. カードの山を、寄り道しても失わない

### 現状

カード学習中に「この節を読む」を押したりタブを移ったりすると、山が丸ごと消える。
`app.js` の `showTab` が画面を作り直すため、`renderFlash` の中に持っていた `deck` が捨てられる。
テスト画面も同じ挙動だが、カードは1つの山が14〜30枚以上と深く、失うものが大きい。

### 方針

**画面を離れるときに、途中の山をモジュールの中に預けておく。** 戻ってきたらメニューの先頭に
「途中の山を続ける（残り◯枚）」を出す。`js/views/player.js` の `pendingOpen`（モジュールの中に
一時的に値を預ける）と同じ流儀である。

- 預ける: teardown の時点で、山が途中（`deck` があり `isDone()` でない）なら預ける。
  記録済みのカードID（`recorded`）も一緒に預ける。これを失うと、再開後に同じカードを
  二重に成績へ記録してしまう
- 戻る: メニューで「途中の山を続ける」を押すと、預けた山と記録済みIDを戻し、表から描く
- 捨てる: 「やめる」を押したとき、「この山を捨てる」を押したとき、新しい山を始めたとき、
  山を最後まで終えたとき

**再読み込みすると消える。** 預け先はメモリで、`localStorage` には書かない。
寄り道（節を読みに行って戻る）を救うのが目的で、日をまたいだ保存は目的にしない。

## 3. アクセシビリティ

### 現状

画面の中身を `innerHTML` で差し替える作りのため、スクリーンリーダーを使う人には
「何かが変わった」ことが伝わらず、押したボタンが消えるとフォーカスが `body` に落ちて迷子になる。

具体的には次の箇所。

| 画面 | 起きていること |
|---|---|
| タブの切り替え | フォーカスがタブのボタンに残り、新しい画面の先頭へ移らない |
| カードの「答えを見る」 | 押したボタン自体が消え、フォーカスが `body` に落ちる |
| カードの判定 | 同上。次のカードの問題文へ移らない |
| テストの解答 | 選択肢が `disabled` になり、正誤と解説へ移らない |
| 模試の問題移動 | 新しい問題文へ移らない |
| 模試のパネル（解答状況・終了確認） | ダイアログとして名乗っておらず、開いてもフォーカスが移らない。閉じても元へ戻らない |
| 保存失敗の帯 | 出現しても読み上げられない |

### 方針

**フォーカスを、次に読むべき場所へ動かす。** 新しい問題文、めくった答え、正誤の判定、
画面の先頭。ボタンが消える場面では必ず移す。

`js/views/a11y.js`（新規）に1つだけ関数を置く。

```js
moveFocus(el)
```

- `el` がもともとフォーカスできない要素（`div` など）なら `tabindex="-1"` を付ける
- `el.focus({ preventScroll: true })` で移す。**スクロールさせない**（目で見ている人の読み位置を動かさない）
- `el` が `null` なら何もしない

`tabindex="-1"` を付けた要素にプログラムでフォーカスを移しても、枠線は要らない（中身を
読ませたいだけで、操作する対象ではない）。CSS で `[tabindex="-1"]:focus { outline: none; }` とする。

### 各画面の扱い

| 画面 | 移す先 |
|---|---|
| タブの切り替え（`app.js` の `showTab`） | `#view` |
| カード: 表を描いたとき | 問題文 `#f-q` |
| カード: 答えを見たとき | 裏 `#f-back-side` |
| カード: 終わり | 「◯枚を覚えました」の見出し |
| テスト: 問題を描いたとき | 問題文 |
| テスト: 解答したとき | 正誤と解説 `#q-after` |
| テスト: 結果 | 「◯ / ◯ 問正解」 |
| 模試: 問題を描いたとき | 問題文 `#m-qtext` |
| 模試: 結果 | 「◯ / 25 問正解」 |

各画面は描画のあとで自分の移す先へ動かす。`showTab` の `#view` は、その後に各画面が
より具体的な場所へ上書きする前提の「最低限」の移動である。

**「後で見直す」を押したときはフォーカスを動かさない。** 押したボタンが残るので迷子にならず、
押した直後にフォーカスが飛ぶとかえって混乱する。

### 模試のパネル

解答状況と終了確認のオーバーレイを、ダイアログとして名乗らせる。

- `role="dialog"`、`aria-modal="true"`、`aria-labelledby`（見出しの要素を指す）
- 開いたら、パネルの中の最初のボタンへフォーカスを移す
- 閉じたら、開く前にフォーカスがあった要素（押したボタン）へ戻す
- Escape キーで閉じる

Tab キーをパネルの中に閉じ込める処理（フォーカストラップ）は作らない。
対象端末はスマホで、キーボードの Tab で移動する使い方はまれである。

### 保存失敗の帯

`role="alert"` を付ける。帯が出たときに読み上げられる。

### 作らないもの

- 「きく」画面の文ハイライトの読み上げ。読み上げ中は音声が既に流れているので二重になる
- フォーカストラップ
- 色のコントラストの見直し（今回の範囲外）

## 4. 構成

| ファイル | 変更 |
|---|---|
| `js/views/mock.js` | `drawExam(active)`、再開ボタンの登録、問題文と結果へのフォーカス、パネルのダイアログ化 |
| `js/views/flash.js` | 山の預け入れと再開、表・裏・結果へのフォーカス |
| `js/views/quiz.js` | 問題文・正誤・結果へのフォーカス |
| `js/views/a11y.js`（新規） | `moveFocus(el)` |
| `js/app.js` | `showTab` で `#view` へフォーカス |
| `index.html` | 帯に `role="alert"` |
| `css/style.css` | `[tabindex="-1"]:focus` の枠線を消す |
| `sw.js` | `CACHE` を上げ、`js/views/a11y.js` を `ASSETS` へ |

`js/lib/` は一切変更しない。テストも増えない（`js/views/` にテストを書かない既存方針）。

## 5. 受け入れ条件

- 保存に失敗している状態で「模試を開始する」を押すと解答画面に入り、最後まで解いて採点できる
- 保存が正常なときの開始・再開は従来どおり動く
- カード学習中に「この節を読む」で離れて戻ると「途中の山を続ける」が出て、同じ位置から再開できる
- 再開後に同じカードを判定しても、成績が二重に記録されない
- 「やめる」「この山を捨てる」で預けた山が消える
- 上の表の各場面で `document.activeElement` が想定した要素になっている
- 模試のパネルが `role="dialog"` を持ち、開くとパネル内へ、閉じると押したボタンへフォーカスが移る
- `npm test` が全件通る（214件）
- オフラインで動作する
